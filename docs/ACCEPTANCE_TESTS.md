# TripMate MVP 手工验收

运行 `.\scripts\run_e_drive.ps1 -SeedDemo`，再按以下场景检查。每个场景都对应 PRD 01 的 P0 验收标准。

## 1. 注册、登录与会话

1. 创建一个用户名、邮箱、密码均有效的新账号。
2. 确认注册后自动进入“发现旅程”。
3. 退出后访问 `/trips`，确认被引导到登录页。
4. 使用用户名或邮箱重新登录。

预期：会话正常；错误密码显示可理解的提示；数据库中不出现明文密码。

## 2. 发布与浏览 Trip

1. 账号 A 发布旅行计划，填写目的地、开始/结束日期、风格、简介和人数。
2. 确认创建后跳转详情页。
3. 账号 B 登录，在列表和搜索结果中找到该计划。

预期：列表显示目的地、日期、创建者和剩余名额；详情显示完整信息。

## 3. 提交同行申请

1. 账号 B 打开 A 的 Trip，填写留言并申请加入。
2. 再次直接访问申请接口或刷新详情。

预期：第一次申请成功；同一用户对同一 Trip 只有一条记录；B 能在“我的旅行”看到等待处理。

## 4. 创建者处理申请

1. 账号 A 进入“申请管理”。
2. 找到 B 的 PENDING 申请并点击“接受同行”。
3. 账号 B 再次查看“我的旅行”和 Trip 详情。

预期：只有 A 可以处理；双方看到 ACCEPTED；详情的已确认同行者出现 B。

## 5. 拒绝流程

1. 第三个账号 C 对仍有名额的 Trip 发起申请。
2. A 拒绝 C 的申请。

预期：A 与 C 都看到 REJECTED；不能重复接受或拒绝该请求。

## 6. 名额与关闭

1. 创建一个期望同行人数为 1 的 Trip。
2. 接受第一位申请者。
3. 使用另一账号尝试申请。

预期：达到人数后 Trip 自动变为 CLOSED；新申请被拦截。创建者也可以手动关闭开放计划。

## 7. 边界与权限

- 结束日期早于开始日期：拒绝创建。
- 目的地、简介为空或异常超长：拒绝提交并显示原因。
- 创建者申请自己的 Trip：拒绝。
- 非创建者处理申请或关闭 Trip：返回 403。
- 缺少 / 伪造 CSRF Token：返回 400。
- 访问不存在的 Trip：返回友好的 404 页面。
